# Managing Degree Pages on the New Website

Executive summary · Draft · November 2026

## The short version

Degree pages are moving into the block editor, but that isn't the real change. The real change is that a degree page stops being a form we fill out and becomes a page we own. Today, every degree has the same layout, fixed in code. We customize it through about 35 fields spread across twelve tabs, and when the layout doesn't suit a program, the only workaround is to build the page by hand. On the new site, every degree starts from a standard layout. From then on, we can rearrange it, remove sections and add new ones, just as we would on any other page.

The Search Service, the program data system the current site already imports from, gives us two kinds of information, and we treat them differently. Facts — credit hours, tuition, deadlines, admission requirements, career outcomes and employment projections — stay connected to the Search Service and update on the page by themselves. Words — the description, highlights, testimonials and careers — are copied onto the page when the degree is created, and from then on they're ours. **The Search Service keeps the facts current, and we own everything a student reads as copy.**

## How a new degree arrives

When a program is added to the Search Service, the next import creates its degree page with the standard layout already in place. The program's current description, highlights, careers and testimonial are written into the page as ordinary text. The page also has the program overview, deadlines and requirements, outcomes and projections, and the shared sections that appear on every degree. It is complete before anyone touches it.

Later imports update the facts and nothing else. They never change the layout, and they never change the text. A catalog rewrite of a program description won't reach a page that already exists, which is the point: once a page is created, its wording is our decision.

That means work on a new degree is optional. A new program has a correct page from its first day, and we spend our time on the degrees where better content makes a real difference.

## What we edit, and what updates itself

- **Facts update themselves.** The Search Service takes in new program data once a month, and our pages pick up the changes within hours of each import. When a fact is wrong for every page that shows it, we fix it in the Search Service, not on the page. The catch is timing. A fix that comes in through the monthly import can take up to a month to appear. We haven't yet confirmed whether a correction can be made directly in the Search Service to get it on the page sooner.
- **The words are ours.** The description, highlights, testimonials and careers are regular text on the page from the day it's created. We edit them like any other copy, and nothing overwrites them.
- **The layout is ours.** We can move sections around. For example, a graduate program with an early deadline can put deadlines above the description. We can also remove a section that doesn't serve a program, or add one that's missing.
- **Editorial sections are ours.** Course overview, skills, admission copy, curated testimonials and news are added from a short set of ready-made degree sections in the editor, then written for each degree.
- **Shared sections are edited once.** Badges, Start Your Application, the UCF Online callout and the message shown when a program has no deadlines posted each live in one place. An edit there changes every degree at once. If one degree needs something different, we detach that section on that page and edit it there.

That puts our effort where it belongs: on the story each program tells, not on re-entering data that already exists somewhere else.

## When a fact needs a different value on one page

Sometimes the Search Service value is correct but can't say what a program needs. A program with variable credit hours needs a range, not one number. A program with an unusual deadline exception needs dates the Search Service can't express. For credit hours, tuition and deadlines, we can enter our own value on that degree, and it replaces the Search Service value everywhere it appears — on the page, in degree search and in what search engines read. Clearing it brings the Search Service value back.

The tradeoff is real. **An override doesn't update.** A deadline that was right in March looks just as authoritative in October, and a student who trusts it can miss an application date. So overrides are built to stay in view. The editor shows the current Search Service value next to ours. If the Search Service value changes after we set an override, that degree is flagged for review. And every override is listed in one place, so we can check them all at the start of each admissions cycle.

Program length works differently. Credit hours are a fact, and the standard layout shows them. Time to completion, like "1–2 years", is copy, and we add it to the page where a program needs it. We shouldn't use the credit-hours override to say "2 years," because degree search and search engines expect a number of hours there.

Overrides should be the exception, not a habit. When the same correction keeps coming up, the fix belongs in the Search Service.

## When the standard layout changes

Every degree gets its own copy of the standard layout, so a change to the standard layout later only affects degrees created after it. That is the price of being able to customize every page, and we think it's the right trade. Degrees nobody has edited can be updated to the new layout automatically. Degrees we've customized are listed for us to update by hand, so nothing we've written is overwritten unless we choose that. We can also list every degree that's missing a particular section, which tells us where a change to that section needs to go.

The standard layout is therefore the most important decision we make before launch. It is the starting point for every degree, and getting it right up front saves hand edits later.

## What goes away

The twelve-tab field form on every degree goes away. That includes Program at a Glance, Deadlines, Start Your Application, Course Overview, Quotes, Skills, Admission Requirements, UCF Online, News and the rest. Their jobs are now done by sections on the page itself, edited where we can see them. The few per-degree settings that remain move into the editor's sidebar: the undergraduate Slate ID for Request Information, the controls that tell the import to leave a degree alone, and the list of that degree's overrides.

The new site also starts fresh. We are not moving the current degree pages over. If we bring curated content across later, that will be a separate project, and it will follow the approach described here.

## What we still need to decide

- **How we correct Search Service data.** Since fixes to facts belong in the Search Service, we need a named process for requesting corrections. Overrides cover the urgent cases on a single page, but we still need to agree on when an override is the right call and when a correction should go to the Search Service instead.
- **Where the line falls between facts and words.** We're treating careers as words and admission requirements as a fact. Either could go the other way, and admission requirements may need overrides like deadlines do.
- **The standard layout.** We need to decide which sections it includes and in what order.
- **Which sections every degree must keep.** We can lock a section so it can be moved but not deleted. Our plan is to start with no locks and add them only if we find we need them.

These are content decisions, not technical ones. They're ours to make, and we should make them before the standard layout is final.
